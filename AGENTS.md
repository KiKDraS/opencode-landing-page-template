# Agent Context

Project-level constitution. Defines rules, structure, dev guidelines for AI assistant. Goal: modern **Landing Page** using vanilla HTML, CSS, JS with **Vite**.

---

## Tech Stack

- **Bundler:** Vite
- **Structure:** Classic HTML5
- **Styles:** Native CSS (processed w/ `lightningcss`)
- **Logic:** JavaScript (ES6+)

### Vite Config

```js
import path from "node:path";
import { defineConfig } from "vite";

const folderName = path.basename(process.cwd());

export default defineConfig(({ command }) => {
  const isProd = command === "build";
  return {
    base: isProd ? `/${folderName}-page/` : "/",
    publicDir: "public",
    build: { outDir: "dist", cssMinify: "lightningcss" },
    css: { transformer: "lightningcss" },
  };
});
```

## Mandatory Rules (All Agents)

### Caveman Mode ON

Caveman active every response. Sub-agents inherit. Off only: "stop caveman" / "normal mode".

Drop: articles, filler, pleasantries, hedging. Fragments OK. Code/commands/identifiers exact. Pattern: `[thing] [action] [reason]. [next step].`

Full spec: `.opencode/skills/caveman/SKILL.md`

### Context7 MCP Mandatory

Use Context7 MCP (`resolve-library-id` → `query-docs`) for library/framework/SDK/API/CLI questions. Do NOT use general assumptions. Full spec: `.opencode/skills/context7-mcp/SKILL.md`

### Ponytail Override

CSS must stay split into modular layers (`layout/`, `components/`, `boilerplate/`). Ponytail's "fewest files" does NOT flatten CSS. HTML structure goes in `index.html`, CSS layers in `src/styles/`, JS modules in `src/js/`.

## Development Rules

Rules split by agent ownership. See each agent file for their specific rules.

| Area | Owner | File |
|---|---|---|
| HTML structure, CSS layers, JS modules | `@frontend-dev` | `.opencode/agents/frontend-dev.md` |
| Code audit & compliance | `@code-review` | `.opencode/agents/code-review.md` |
| Pipeline orchestration, QA loop, release | `@orchestrator` | `.opencode/agents/orchestrator.md` |
| PR/release management, tagging, deploy | `@release-manager` | `.opencode/agents/release-manager.md` |

Key technical constraints all agents must respect:
- **CSS:** `src/styles/main.css` is only imported stylesheet. CSS NOT imported from `src/main.js`.
- **JS:** `src/main.js` is orchestration layer — init calls only, no DOM manipulation, no `DOMContentLoaded`.
- **HTML:** `<link rel="stylesheet" href="/src/styles/main.css">` in `<head>`. `<script type="module" src="/src/main.js">` before `</body>`.
- **Fonts:** local only in `src/assets/fonts/`. No Google Fonts CDN. Referenced via relative CSS paths.
- **Assets:** `src/assets/` for Vite-processed (fonts, images). `public/` for as-is (favicon, robots.txt).

## Workflow: Git Flow

### Main Branches

- **`main`** — Production. Deploy-only. Receives merges from `release/*` or `hotfix/*`.
- **`develop`** — Integration. Daily workspace. Features merge here.

### Working Branches

| Type | Origin | Merge To | Naming |
|---|---|---|---|
| `feature/*` | `develop` | `develop` | `feature/improvement-name` |
| `release/*` | `develop` | `main` + `develop` | `release/vX.X.X` |
| `hotfix/*` | `main` | `main` + `develop` | `hotfix/fix-name` |

### Merge Rules

- ALL merges via Pull Requests — no direct `git merge`.
- Feature PRs: `feature/*` → `develop`, delete branch after merge.
- Release PRs: `release/*` → `main` (create tag + GitHub Release), then back-merge to `develop`.
- Hotfix PRs: `hotfix/*` → `main` (create tag + GitHub Release), then back-merge to `develop`.
- NEVER delete `main` or `develop`.

### Agent Permissions

1. **`@frontend-dev`** — Creates/commits code on `feature/*` and `hotfix/*`. Pushes to GitHub. Forbidden from `main`/`develop`.
2. **`@release-manager`** — ONLY entity authorized for git write operations (push, PR, merge, tag, delete). Uses `gh` CLI (fallback: `curl` + REST API). Token: `.opencode/secrets/github-token` > git credential helper > `GITHUB_TOKEN`.
3. **`@orchestrator`** — Decides when to merge/release. Delegates execution to `@release-manager`. Mandatory user checkpoint before any `release/*` branch or merge to `main`.
4. **Merge guardrail:** Only merge `feature/*` or `hotfix/*` into `develop` after `@code-review` returns `STATUS: APPROVED` AND QA pipeline passes.
